## What Is AI Editor?

AI Editor is a full-stack, AI-assisted video editing pipeline. It accepts a reference video and a set of source clips, uses computer vision and an LLM to understand the target style and structure, assembles a stage-based edit plan, renders the output via the Shotstack cloud rendering API, and optionally converts the result to a vertical Short for YouTube.

This is not a wrapper around a chat API. It is a multi-stage media pipeline with a FastAPI backend, React frontend, orchestration layer, OCR/scene analysis, external rendering integration, and export workflows.

## Core Features in This Release

- **Reference video analysis** — SceneDetect-based shot boundary detection, EasyOCR and PaddleOCR text extraction from frames
- **Conversational brief builder** — Groq LLM-powered chat interface that refines a natural language brief into a structured edit plan JSON
- **Stage-based pipeline orchestrator** — `pipeline/runner.py` executes ordered stages with per-job state persistence and artifact isolation under `tmp/jobs/<job_id>/`
- **Shotstack timeline assembly** — `ai_editor/editor.py` programmatically constructs Shotstack render specs from clip lists, overlays, and timing metadata
- **Overlay planning** — `overlay_planner.py` schedules text/graphic elements respecting scene boundaries and duration constraints
- **Shorts conversion** — automatic 16:9 → 9:16 reframe and post-processing for vertical delivery
- **YouTube upload** — OAuth 2.0 direct publish with metadata control
- **Google Drive ingestion** — service account and OAuth-based asset retrieval
- **React frontend** — job submission, stage progress tracking, Drive/YouTube OAuth flows
- **Docker support** — single-container build for local and server deployment
- **Unit tests** — pytest coverage for normalization edge cases, overlay policy, and text segment logic

---

## Technical Highlights

- `pipeline/runner.py` is the core orchestrator (~60 KB) coordinating all pipeline stages
- Per-job artifact model: every job writes its state, plans, and outputs to an isolated directory
- LLM output is structured into a machine-readable JSON edit plan — not used as free-form text
- Shotstack timeline is assembled programmatically from clip metadata, not manually authored
- OCR pipeline supports both EasyOCR (fast) and PaddleOCR (higher accuracy) backends
- Google OAuth flow handles both service account (Drive read) and user OAuth (YouTube publish)

---

## Known Limitations

- Shotstack rendering is asynchronous; the backend polls for completion and long jobs may require extended wait time
- PaddleOCR has a large install footprint (~2 GB with dependencies); a lighter backend is on the roadmap
- Google Drive OAuth tokens may require manual refresh in some environments
- No built-in task queue; concurrent jobs run in in-process threads
- Frontend does not yet support drag-and-drop clip reordering

## Setup Notes

1. Copy `.env.example` to `.env` and fill in your `SHOTSTACK_KEY` and `GROQ` keys at minimum
2. A Shotstack **Stage** key is free and sufficient for development
3. Google Drive and YouTube integrations require a Google Cloud project with the relevant APIs enabled
4. See `docs/SETUP_GUIDE.md` for the full setup walkthrough
5. See `docs/DEPLOYMENT.md` for Docker-based deployment
